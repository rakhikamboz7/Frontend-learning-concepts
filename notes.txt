a scope/closure issue if a for loop used var to create asynchronous callbacks, causing all callbacks to reference the same index.

3. why :
The bug was due to var i inside a loop with setTimeout. Since var is function-scoped, all callbacks used the final value of i.
Closures capture variables, not their values. When setTimeout runs, the loop has finished and i equals data.length

2. Learned about Why is `innerHTML +=` bad?
Answer with key points: 
- Re-renders entire DOM each time
- Performance issue
- Hard to maintain

Better:
createElement+appendChild
It is perfectly fine to use innerHTML when you want to completely wipe a
container or insert a simple, static string that you wrote yourself (not from an API),
such as:

dataOutput.innerHTML = ''; (To clear the list).
dataOutput.innerHTML = '<p>Loading...</p>'; (A simple message).

In your script.js, we used dataOutput.innerHTML = ''; once at the start to
clear the "Loading" message, but then used document.createElement inside the
loop for the actual user data to ensure the app remains fast, secure, and professional.
